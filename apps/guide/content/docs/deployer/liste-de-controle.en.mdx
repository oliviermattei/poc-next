Go through this list before opening your SaaS to the public. Each item says how to check it, and links to the page that explains it.

## Configuration

- [ ] **`NODE_ENV=production`.** It is what makes the dangerous local modes refused. The Docker image sets it itself.
- [ ] **`AUTH_SECRET` is specific to this deployment**, generated by `openssl rand -base64 32`, never the one from `.env.example`.
- [ ] **`APP_URL` is the exact public address, in `https://`**, with no path and nothing after the domain. See [Domain and two hosts](/en/deployer/domaine-et-deux-hotes).
- [ ] **`DATABASE_URL` points to the production database.**
- [ ] **No test or build variable**: `NEXT_PHASE`, `SKIP_ENV_VALIDATION`, `OAUTH_LOCAL_PROVIDER`, `PAYMENTS_RECORDED_EVENTS`, `I18N_MISSING_KEY_PROBE`, `CONSENT_SCRIPT_PROBE` and `INNGEST_BASE_URL` are absent or empty.
- [ ] **`SUPERADMIN_EMAIL`** contains the address of the account that will administer the console. Without it, the console answers 404 to everyone (startup warns, without refusing). See [Superadmin console](/en/fonctionnalites/console).
- [ ] **The application starts**: no `Démarrage refusé : …` ("Startup refused") line in its logs. Otherwise: [Troubleshooting](/en/reference/depannage).

The full table: [Environment variables](/en/configurer/variables-d-environnement).

## Your modules’ services

For each enabled module, either the provider is connected or the module is turned off (`pnpm ks toggle <module>`, see [Modules](/en/configurer/modules)).

- [ ] **Emails**: `RESEND_API_KEY` and `EMAIL_FROM`, on a domain verified at Resend (SPF, DKIM, DMARC), and `EMAIL_LOCAL_CAPTURE` removed. Otherwise no email is sent. See [Resend](/en/services/resend).
- [ ] **Payment** (`billing`): `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, and the `<APP_URL>/api/modules/billing/webhook` webhook declared at Stripe. See [Stripe](/en/services/stripe).
- [ ] **Storage** (`storage`): the four `STORAGE_S3_*` variables, and the bucket origin in `config/security.ts`, `connect` field. See [S3 storage](/en/services/stockage-s3).
- [ ] **Background jobs** (`jobs`): `INNGEST_EVENT_KEY`, `INNGEST_SIGNING_KEY`, and the `<APP_URL>/api/modules/jobs/inngest` address declared at Inngest; or `JOBS_LOCAL_RUNNER=1` on **a single instance**. See [Inngest](/en/services/inngest).
- [ ] **Google or GitHub sign-in**, if you use it: both variables of each pair, and the callback address declared at the provider. See [Google](/en/services/google) and [GitHub](/en/services/github).
- [ ] **Analytics**, if you use it: `POSTHOG_KEY`, `POSTHOG_HOST`, and the host in `config/security.ts` (`connect` and `img`). See [PostHog](/en/services/posthog).
- [ ] **Error tracking**, if you use it: `SENTRY_DSN`, `SENTRY_RELEASE`, and the source maps sent. See [Sentry](/en/services/sentry).

## The database

- [ ] **Migrations run before each release**, and the command prints `Migrations appliquées…` or `Rien à appliquer…`.
- [ ] **`pnpm db:seed` has never been run** against the production database.
- [ ] **Backups are in place**, copied off the server, and a restore has been tried.

See [Production database](/en/deployer/base-de-donnees-en-production).

## Network and security

- [ ] **HTTPS** on every domain served.
- [ ] **A relay in front of the application**, which **overwrites** `x-forwarded-for` and forwards `Host`. The application’s port is not open directly to the Internet. See [Docker and Coolify](/en/deployer/docker-et-coolify#the-relay-in-front-of-the-application).
- [ ] **Dependencies are audited**: `pnpm run audit` passes. Today, it reports vulnerabilities that the project must address ([#77](https://github.com/oliviermattei/poc-next/issues/77)).
- [ ] **Secrets are nowhere in the repository**: `.env.production` is not committed (`git status` does not show it).

## Your product

- [ ] **Offers and prices** are yours. See [Offers and prices](/en/configurer/offres-et-prix).
- [ ] **The name, texts and legal pages** are yours. See [Site and legal pages](/en/configurer/site-et-pages-legales).
- [ ] **The sender and email texts** are yours. See [Emails](/en/configurer/e-mails).
- [ ] **Modules you don’t need are turned off**, and you have decided what to do with the `demo-enabled` demonstration module. See [Demonstration module](/en/fonctionnalites/module-de-demonstration).

## After going live

1. Open `<APP_URL>/api/health`: you should see `{"status":"ok","database":"connected"}`.
2. Create an account with a real address: the verification email must arrive, and its link must start with your `APP_URL`.
3. If `billing` is enabled: subscribe to an offer with a Stripe test card (test keys), then check that the subscription appears in the billing settings.
4. Sign in with the `SUPERADMIN_EMAIL` account, then open `/console`.
5. Put `<APP_URL>/api/health` under monitoring.

## Known limits to keep in mind

<Callout type="warn" title="What has not been proven yet">
- No real deployment has been made yet, neither on Coolify nor on Vercel ([#145](https://github.com/oliviermattei/poc-next/issues/145)).
- Two-host mode has only been tested locally ([#73](https://github.com/oliviermattei/poc-next/issues/73)).
- Rate limiting depends on a relay that overwrites `x-forwarded-for` ([#78](https://github.com/oliviermattei/poc-next/issues/78)).
- The password-reset token is stored in plain text in the database ([#79](https://github.com/oliviermattei/poc-next/issues/79)): protect access to your database and its backups.
- The S3 bucket origin must be written in `config/security.ts` ([#144](https://github.com/oliviermattei/poc-next/issues/144)).
</Callout>
