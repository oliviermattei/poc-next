## Fifteen keys mandatory from the first module, and one optional

A module declares `id`, `requires`, `schema`, `migrations`, `routes`,
`navigation`, `publicUrls`, `messages`, `emails`, `webhooks`, `jobs`,
`dataCategories`, `retention`, `purge` and `export` — empty if need be: adding
one later means reopening every module already written.

Exactly one key is **optional**: `seeds`, the module's demonstration data
(ADR 069). A module that declares none is not incomplete — it is silent, and the
registry aggregates only what is declared. It is the single exception, and a
motivated one: made mandatory, it would have reopened every module already
written just to add an empty array.

## Four layers

`domain` carries the pure rules, `application` the use cases, `infrastructure`
the access to outside resources and `presentation` what gets rendered. The last
two never import each other, and lint refuses it — not review.

> A rule no command checks is documentation, not a rule.

## Generate, do not guess

`pnpm ks scaffold <module>` produces a compliant skeleton. Writing one by hand
is a smell.

Enabled modules are declared in [`config/`](/docs/prise-en-main/configurer), and
the repository comes up first: [install the repository](/docs/prise-en-main/installer).
